1. What this page is

3. Workforce register
  • Waiting for your approval: every piece of work an agent has prepared and stopped on. Nothing is sent, filed, paid or changed until you decide. Same queue as Slack (#agent-approvals) and the Tasks drawer, decided the same way.
  • Check these: what should have moved and has not. Absence and stuckness, never a list of successes.
  • Workforce register: every agent, its goal, guardrails, status, workload, accuracy, its AGENTIC spec, its compiled prompt, its learning log and its daily decisions.

Building an agent's SOP from a video stays on the Systemisation page. This page is where agents are managed and judged.

2. The approval queue (zone 1)

The queue shows ONLY loop-raised work: tasks at Status Approval that carry a Sent For Approval By agent link. Legacy records parked at Approval status never appear. Each card leads with the one-line ask (the agent's own "Carrying this out will involve" line), then the agent's full work, the brief it was given, and the age it has been waiting. Tier 1 items carry a red banner: read those fully before deciding.

The four actions and exactly what each writes

This page is the third face of ONE mechanism. It writes the same fields as the Tasks drawer and the Slack loop, so the three surfaces can never disagree.

ActionWhat it meansWhat is written to the task
ApproveRelease the work. The agent carries it out, then completes the task itself.Approval Outcome = Approved as-is · Approved At = now · Approved By = Kevin · Status = Today · Due Date = today · Completion Date cleared · task handed back to the agent (Team Member + Sent For Approval By = the agent, Assignee cleared)
Approve with minor editsYou tidied it first. Still counts as accurate work.Same as Approve, with Approval Outcome = Approved with minor edits
Request changesBack to the agent to redo. A comment is required; your words are the instruction.Approval Outcome = Changes requested · Approval Feedback = your comment · Approved At/By stamped · Status = Today, due today, handed back to the agent
RejectKill the work entirely. A reason is required and a confirm dialog stands in the way. Counts against the agent's accuracy.Approval Outcome = Rejected · Approval Feedback = your reason · Status = Completed · Completion Date = now · agent links set as above

Every decision also leaves an Airtable comment on the task, and the optional "Kind of work" picker sets the Task Type used to score the agent per job type.

Stale-approval guard: a click approves what was on screen when the card rendered. Before writing, the page re-reads the task; if it changed since (or was decided in Slack or the drawer), the decision is refused with a message and the queue reloads. Same principle as the Slack baseline guard.
Approving is not completing. Approve hands the task back to the agent to carry the action out. Kevin never marks agent work Completed.

3. Check these (zone 2)

Five lanes, each reporting absence. A lane that cannot be read shows a fault line, never a clean slate. When all five run clean the zone says: "Nothing needs you – all agents moving."

Stuck tasksTasks at Today/Overdue owned by an AI agent, past their due dateWork that should have been done and has not moved

Daily logsBuilt or Live agents that wrote nothing to the AI Agent Daily Log todaySilence means the agent did not run, or its log write broke
GuardrailsAny automatic guardrail tightening in the last 7 daysThe system pulled a leash in on falling accuracy; you should know

4. The workforce register (zone 3)

  • Role agents: one row per role-specific agent from the AI Agents table. Click a row for its panel: the seven AGENTIC stage fields (editable), a readiness check button, the accuracy band suggestion, "Compile prompt" (builds the one working prompt from the card), the learning log, and "Daily decisions" read from the AI Agent Daily Log.
  • Guardrails: tightening is automatic when accuracy drops (worst job type with 20+ checked pieces decides the band). Loosening is always your click, via the dropdown.
  • Strategic layer: the AI CEO, department heads and generic workers (Team Members rows), shown with workload only.
  • Process agents: workflows whose SOP runs as an agent (the video route). Their panel carries the identity card, the autonomy ladder, testing/live controls, the proposal feed with Approve/Reject/Undo, and per-action permissions. "View SOP" opens the workflow on the Systemisation page.
  • + Create an agent: the guided form walks you through the seven AGENTIC questions with an AI check on each answer.

5. Health checks

The sync bar at the top of the page runs seven checks; the sidebar dot in the shell mirrors the worst of them.

CheckIf it fails
Approvals queue readAirtable auth or a broken formula. Hit Refresh; if it persists, the Status or Sent For Approval By field name changed.
Legacy Approval records excludedA task with no raising agent leaked into the queue. The filter broke; do not decide legacy records here.
Agents register readThe AI Agents or Team Members read failed, or the Is AI Agent / Active fields were renamed.
Daily log readThe AI Agent Daily Log table could not be read; the daily-log lane is blind.
Accuracy stats controlZero approval history matched. On a platform with weeks of decisions, zero means a field rename, not a quiet week.
Inbound Comms Response metric freshThat agent's register row lost its Metric Score. Its runtime stopped publishing; check the triage job.
Check zones computedOne or more lanes could not run. Treat those lanes as unknown, never as clear.
