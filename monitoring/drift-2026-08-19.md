## 3. SOP Drift

### `os/tasks/sop.html` ↔ `os/tasks/index.html` — 11 filed

Chosen because it was the least-covered pair in the mapping table: last deep-audited 9 Aug,
while `sop.html`/`sop-invoices` were done 14 Aug, `sop-cfvs`/`sop-sitemap`/`sop-coa` on
16 Aug and `sop-compliance` on 18 Aug. It also carries the widest version gap in the whole
registry — page **1.131** against SOP **1.3** — and the SOP's own header still reads
"Version 1.1 · 17 Apr 2026" against a 9,667-line page last touched 14 Aug.

**This is the most drifted pair found so far.** The SOP documents a page that no longer
exists in several structural respects.

- **`-220` (high)** — `os/tasks/jobs.html` was deleted on 24 Apr 2026 (commit `0289148`).
  The SOP still gives it a quick-reference row, a capability bullet, an entire section 8
  with a contractor setup walkthrough, a localStorage key nothing writes, and a
  troubleshooting entry. `os/tasks/sop.html` is now the **only** file in the repo that
  mentions it. A contractor following the SOP opens a 404. The replacement is the in-page
  "Contractor Tasks" tab.
- **`-221` (high)** — `autoRescheduleOverdue` (`index.html:5215`) is the **only one of 18
  `patchTask` call sites** that discards the Response. `patchWithRetry` returns a non-ok
  Response after exhausting its 429/5xx backoff rather than throwing, so a failed reschedule
  still mutates `t.dueDate = today` locally and still counts toward the "rescheduled N tasks"
  notice. The batching immediately above it is inert as well: `overdue.map()` fires every
  PATCH eagerly, so the chunked await and 250 ms sleep throttle nothing.
- **`-222` (high)** — the SOP documents six views. The tab bar renders **ten**
  (`index.html:513-522`). Approvals (with a live count badge), Contractor Tasks and Meetings
  are undocumented anywhere. The SOP contradicts itself: section 3 says six, section 12
  refers to "the AI Agents tab".
- **`-223` (medium)** — `STATUS_OPTIONS` has no `To do` and `PRIORITY_OPTIONS` has no `High`
  (`:869-870`); `High` survives only as a `High (legacy)` option shown when a task already
  holds it. Both values still exist in Airtable and the SOP documents both as normal
  choices, so a task set to `To do` in Airtable cannot be moved off it, or filtered for,
  from the page. Worth noting alongside this: the drift-monitor skill's own single-select
  table still lists both as permitted values for a routine writing a task.
- **`-224` (medium)** — the SOP says twice that the Task List "deliberately excludes
  Project-priority tasks"; `getFilteredTasks` has no such exclusion. It also says Completed
  tasks are "excluded from all live views", but the status filter's "Completed (history)"
  mode loads them.
- **`-225` (medium)** — the calendar proxy now requires a `gcal_proxy_key` token in
  localStorage. Without it the proxy answers `unauthorized` and `fetchCalendarEvents`
  returns `[]` after a `console.warn` only — indistinguishable on screen from an empty day.
  `GCAL_SCRIPT_URL` is hardcoded and non-empty, so the SOP's troubleshooting advice to
  "check that GCAL_SCRIPT_URL is set" always passes and the documented "Calendar: not
  connected" note never appears for this failure.
- **`-226` (medium)** — section 5 states the page "does not provide a create-task form — it
  is a read and update interface only". There is a full Add Task modal, an Add Project
  modal, and the global floating "+ Task" FAB from `js/quick-task.js`.
- **`-227` (medium)** — weekly capacity is per-person and editable from a cog on each
  capacity card, stored in `_task_capacity_<key>`, defaulting to 40 only when unset. The SOP
  presents 40 hrs as a constant. Two people on different devices can therefore see different
  utilisation percentages and different colour bands for the same workload, with nothing on
  screen saying the figure is local to that browser.
- **`-228` (low)** — section 10 documents four filter controls; the bar has eight. The four
  undocumented ones are the triage-useful ones: Project, Recurring, Hard deadline, Time
  Estimate, plus an Owner Type filter that splits AI-agent work from human work.
- **`-229` (low)** — auto-reschedule also skips `hardDeadline` tasks. The SOP lists four
  conditions and its troubleshooting entry names only Some Day.
- **`-230` (low)** — the localStorage table lists the dead `_task_contractor` and omits four
  live keys (`_task_capacity_<key>`, `_task_starttimes_<date>`, `_slack_notified_tasks`,
  `gcal_proxy_key`).
