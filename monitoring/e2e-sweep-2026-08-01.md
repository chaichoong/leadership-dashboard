## Why this run is degraded

`mcp__Claude_Browser__javascript_tool` was denied by the Claude Code auto-mode permission
classifier — twice, including for a trivial read-only evaluation:

1. `localStorage.setItem('_dlr_pat', …)` → denied
2. `PAGE_REGISTRY.map(p => p.id)` (pure read, no writes) → denied

So JS evaluation is blocked wholesale, not just the token write. Per the task file I did **not**
type the token into the login field (prohibited), and did not place it in the served web root.
I fell through to the documented fallbacks instead: screenshot to prime the viewport →
`read_page filter:"all"` to enumerate the sidebar → click-based navigation.

**Consequence:** every panel rendered its shell behind the auth overlay with no Airtable data
behind it. A clean click and a clean console therefore do **not** prove a tab works. All 18 tabs
are marked UNVERIFIED, not PASS.

## Failures needing attention

### 1. [FAIL] `javascript_tool` denied — the sweep cannot authenticate

The permission classifier blocks all browser JS evaluation for this scheduled task, so the token
cannot be injected into `localStorage._dlr_pat` and the app never boots authenticated. Every
morning this silently downgrades the sweep to shell-only checks: **data rendering, KPI values,
badges, counts and every figure on every tab go unchecked.**

Fix: pre-approve `mcp__Claude_Browser__javascript_tool` for the `prod-e2e-sweep` task, then the
sweep returns to FULL mode on its own. Until that happens this FAIL will recur daily and the
sweep's green results mean far less than they look like they do.

### 2. [WARN] Cache-bust drift on `css/sync-bar.css` — shell says v=3, all 16 other pages say v=2

`index.html` requests `css/sync-bar.css?v=3`; every other page requests `?v=2` — including the
iframe pages the shell actually loads (`os/tasks`, `os/operations`, `os/strategy`,
`os/business-plan-builder`, `compliance.html`, `follow-up.html`) and the whole `*-supabase.html`
shadow build.

Traced to commit `1a60a56` (2026-07-21, "Add Page guide button + plain-English guide for the
Wealth tab"), which changed `css/sync-bar.css` and bumped `index.html` to v=3 but left the other
pages on v=2. Any returning browser with a cache warmed before 21 Jul serves a stale sync-bar
stylesheet inside those iframes. Cosmetic, low severity, but it is exactly the "bump the
cache-bust version as part of the change" rule in CLAUDE.md going unfollowed.

## Notes for tuning this sweep

The task file's degraded-mode guidance held up well — the fallback chain worked exactly as
written and produced real signal (nav wiring, iframe loads, per-tab console, invariants) without
JS. Two things worth adding to the task file from this run:

1. Under the auth overlay, `read_page filter:"interactive"` only returns sidebar and overlay
   elements, so panel controls are unreachable for the read-only interaction step. The AI
   Assistant toggle is a reliable JS-free substitute.
2. `read_network_requests` is the strongest degraded-mode evidence available — it proves the
   iframe pages actually fetched and returned 200. Worth promoting into the documented flow.
