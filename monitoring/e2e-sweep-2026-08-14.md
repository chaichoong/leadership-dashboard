## Dedupe check (STEP 5)

Finding key: `e2e-auth-js-denied`.

A first pass of both the key query and its control returned **zero rows each**, which under the skill's
rule means "the query is broken, create nothing". That was the right call, and the cause is worth
recording because it is the exact silent-zero trap in project memory:

- The requests carried `fields[]=Name`, but the Tasks table's primary field is **`Task Name`**. Airtable
  returned an error object, not a record list, and the parser's `.get('records', [])` turned that error
  into a confident zero.
- Re-run with `fields[]=Task Name` and the raw response printed: the control returned **2** keyed tasks
  (`recaFnWr9MNOeP86P`, `recrGG00unq8Pup2V`) and the target key returned **1** (`recrGG00unq8Pup2V`).

**Action taken:** the existing task `recrGG00unq8Pup2V` was updated with a dated recurrence line and its
due date refreshed to 2026-08-14. No new task was created. Had the control not been re-verified, this
sweep would have written the duplicate the check exists to prevent.
