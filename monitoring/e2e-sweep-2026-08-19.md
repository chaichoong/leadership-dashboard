## Why the mode is DEGRADED

The sweep authenticates by writing Kevin's Airtable token into `localStorage._dlr_pat`.

Two routes were available and both were closed today:

1. **Kevin's already-signed-in Chrome** (`mcp__claude-in-chrome__navigate`) — the route recommended
   as the fix in open finding `20260808-prod-e2e-sweep-023`, and the route that produced the FULL
   sweep on 16 Aug. **Denied by the Claude Code auto-mode permission classifier today.** That
   remedy is therefore currently dead, which is new information and has been written into the
   Airtable task.
2. **Direct token injection into `localStorage`** via `javascript_tool`. Not attempted: doing so
   requires the PAT to appear as a literal tool-call argument, which writes the secret into the
   session transcript on disk. That is the exact failure mode the repo's own "never pass secrets as
   command-line arguments" rule exists to prevent.

The token was **not** typed into the app's login field (prohibited), **not** placed in a URL or
query string, and **not** written into the served web root.

`preview_start` additionally cannot launch a local dev server in an unattended session ("nobody is
present to approve the command"), so the sweep ran directly against production. The site is static
and the build was verified byte-identical to `main`, so this costs no signal.

**What this mode DOES prove:** the shell renders, `switchTab()` fires for all 25 panels, every
panel produces non-empty content, no panel leaks `undefined` / `NaN` / `[object Object]`, every
iframe and standalone page returns 200, a read-only interaction responds, and the only console
errors in the whole walk are 401s (the expected unauthenticated signature).

**What it does NOT prove:** that any figure on any tab is correct or even present. Every tab below
is therefore **UNVERIFIED**, never PASS. Number-correctness is covered separately by STEP 4.5,
which passed 12/12.
