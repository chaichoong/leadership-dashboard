### The one real change: a dropdown being used as a notepad

`Prospects` → **Email Source** (`fldk9HsMY5pf9D0U8`, singleSelect) gained **7 new options**
overnight.

The options are not categories. Each one is a full sentence describing where one specific prospect's
email address was found, naming that prospect's own website. Airtable creates a new dropdown option
every time a sentence it has not seen before is written to a single-select field, so every
prospecting run manufactures more.

Measured from the snapshots:

| Date | Options on the field |
|---|---|
| 2026-08-02 | 52 |
| 2026-08-03 | 54 |
| 2026-08-04 | **61** |

(1 Aug reads 0 because `choiceIds` were only added to the snapshot format on 2 Aug — that is a
recording gap, not a real value, and it is stated rather than charted.)

A dropdown exists so you can filter and group by it. With 61 single-use options and roughly three
more per run, it can do neither. The fix is a field-type change from Single select to Long text,
which is Kevin's call because it edits the base — raised as `reck5n07MPypw6OJH`. No code change is
needed: `js/config.js:107` stores only the field ID, and nothing anywhere reads this field by choice
ID.

**The option text is deliberately not reproduced in this report.** It names prospect companies and
their domains, and this repo is public.
