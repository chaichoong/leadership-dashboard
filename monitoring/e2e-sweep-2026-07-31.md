## Failures needing attention

### 1. [FAIL] Auth injection blocked — the sweep ran blind to data

`mcp__Claude_Browser__javascript_tool` was denied by the Claude Code auto-mode permission
classifier when setting `localStorage._dlr_pat`. After that denial, **all** JS evaluation was
denied, including read-only reads such as `PAGE_REGISTRY.map(p => p.id)`.

Consequence: the app was walked logged-out. Every panel sits behind the auth overlay, so no tab
could be confirmed to render real Airtable data. All 18 tabs are **UNVERIFIED**, not PASS.

Per the task file's own rules, the token was **not** typed into the login field, **not** placed in
a URL, and **not** written anywhere in the served web root.

**Fix:** pre-approve `mcp__Claude_Browser__javascript_tool` for this scheduled task, otherwise the
sweep silently degrades to a shell-only check every morning.

### 2. [WARN] `config.js` cache-bust drift between the shell and two OS pages

Browsers cache by full URL, so a `?v=` pin that lags means a returning visitor keeps serving a
stale `config.js` on that page while the shell gets a fresh one.

| Page | Pins |
|---|---|
| `index.html` and all `*-supabase.html` | `config.js?v=50` |
| `os/team/index.html` | `config.js?v=23` |
| `os/strategy/index.html` | `config.js?v=22` |
| `os/strategy/index-supabase.html` | `config.js?v=22` |

Confirmed live: the network log for the Team Members tab shows
`GET .../js/config.js?v=23 → 200`.

This is the exact failure class CLAUDE.md flags as high stakes — `config.js` carries the field ID
constants and `AI_MODEL_DEFAULT` / `AI_MODEL_LIGHT`, and a retired model ID is an app-wide AI
outage. Two OS pages are up to 28 cache-bust versions behind the shell.

Lower-stakes instance of the same drift: OS pages load `css/sync-bar.css?v=2` while the shell
loads `?v=3`.

Not fixed in this sweep — this is a read-only run, and the task file says to report rather than
repair.
