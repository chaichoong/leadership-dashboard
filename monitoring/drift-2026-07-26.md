### Sync-invariant gate FAIL — full diagnosis

Running `npx playwright test` reproduced **deterministically** (twice, not flaky):

```
two-way-sync.spec.js:38   expected withoutFieldId ≤ 2, received 3
stale-data-protection.spec.js:41   same root cause
```

Both tests load `/`, count GET fetches to `api.airtable.com` that omit `returnFieldsByFieldId=true`,
and allow at most 2 (the Fintable exception). Three now fire on load:

| # | Table | Fetch site | Added | Reads response by |
|---|---|---|---|---|
| 1 | `tbl1nr0EcX2T62KME` accounts (Fintable sync) | js/fintable.js | historical | field name — allowed exception |
| 2 | `tblZ75JgE1wzDP0ps` AI Brain feed | [js/shared.js:111](js/shared.js) | 2026-07-15 (e13426b) | field name (`f.Kind`/`f.Status`/`f.Answer`) |
| 3 | `tblJ3GFnAAoXf99e9` Agent activity | [js/dashboard.js:983](js/dashboard.js) | 2026-07-06 (3db7024) | field name (`r.fields['State']`/`['Agent']`) |

Fetches 2 and 3 **intentionally** omit the flag because they parse by field name, so they work
correctly — this is not a data bug, no field silently reads `undefined`. It is the test's hard-coded
"≤2 exceptions" budget going stale as new name-based feature fetches were added. Neither commit that
added them touched the tests, and prior daily pushes appear to have gone in without this gate
active in their environment (the pre-push hook is installed locally, not committed to the repo).
