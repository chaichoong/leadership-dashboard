Impact assessment: no client-facing impact observed. The app renders correctly on every tab
and all three live data invariants pass, so real data is not corrupted. But a red gate on main
means every push is currently blocked unless bypassed with `SKIP_SYNC_TESTS=1`, which erodes the
safety net. Note the possible contradiction to flag for a human: CLAUDE.md's "Known Anti-Patterns"
says this codebase reads Airtable fields by NAME (via the `F` constants), NOT by field ID — yet
these two tests assert requests use `returnFieldsByFieldId=true`. So either (a) the app regressed
and stopped sending `returnFieldsByFieldId`, or (b) the app intentionally moved to field-name reads
and these two tests are now stale and should be updated. A human needs to decide which — this
read-only sweep does not change code. Raised to Kevin via Slack + an Airtable [WARNING] task.

This report was committed with `SKIP_SYNC_TESTS=1` because the change is documentation-only and
the failures are independent of it; bypassing was the documented escape hatch for exactly this
false-red-for-this-change case, and the failure is surfaced here rather than hidden.

## Notes for sweep tuning
- Two registry entries have no in-shell panel and full-navigate the top document: `compliance` (`standalone: compliance.html`) and `how-it-works` (`standalone: how-it-works.html`). Calling `switchTab()` on these unloads the app shell, which stalls any in-shell JS loop. This is expected app behaviour (standalone pages), not a bug. The in-shell sweep loop should skip these two ids and verify them by direct navigation instead — handled correctly this run.
- App globals (`PAT`, `allTransactions`, `allCosts`, etc.) are `const`-declared lexicals, NOT `window` properties — check them via bare references, not `window.PAT`. `window.switchTab` and `PAGE_REGISTRY` are reachable. (Prior sweeps that read `window.PAT` would have wrongly concluded unauthenticated.)
- The browser javascript_tool follows the last-focused frame; after switching to an iframe tab, reads can land in the iframe context. Writing sweep results to `localStorage` (shared per-origin across frames) makes them readable regardless of active frame — used this run to survive the frame hops.
- Live unreconciled count moved 14 → 24 during the run after a manual refresh (initial view was cached "data from 23h ago"); both are legitimate live values, not a defect.
