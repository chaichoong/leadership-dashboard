📋 1. Overview & Purpose

Task and Project Management is a self-contained web application that provides the operations team with a unified view of all tasks and projects stored in Airtable. It is designed for daily operational use by Kevin Brittain, Mica Albovias, and Ericamae Atenta, and covers contractor maintenance work (Gary Marsh, Rob Jackson, Roy Lavin) on its own Contractor Tasks tab.

The system fetches all non-completed, non-someday tasks from Airtable on every load and presents them across ten specialist views. Tasks can be updated in real-time — status changes and due-date adjustments write directly back to Airtable via the REST API. No separate backend is required.

Start on My Day. It opens by default and answers the only question most days need: what am I doing now. Every other tab is there when you want a different slice of the same tasks.

Key capabilities

  • Ten views: My Day, Approvals, Task List, Kanban (by week), Projects, Capacity, Recurring, Contractor Tasks, Meetings, and AI Agents
  • Smart Daily Planner that slots tasks around calendar events and personal routines
  • Google Calendar integration via a Google Apps Script proxy
  • Automatic rescheduling of Kevin's overdue tasks to today on every load
  • Team and personal identity switcher (each user sees their own tasks by default)
  • Bulk operations: mark multiple tasks complete or reschedule them in one action
  • Drag-and-drop Kanban board for scheduling project tasks across calendar weeks
  • Contractor Tasks tab: every open maintenance job, grouped by property, with live reassignment between Gary, Rob and Roy
  • Approvals tab: what the AI agents need a decision on, and what they finished once you gave it
🔑 2. How to Access
1

First-time setup

One-off
  1. Open os/tasks/index.html in your browser (or click Tasks & Projects in the Operations section of the sidebar to load it as an iframe).
  2. If prompted, enter your Airtable Personal Access Token (starting with pat_) in the auth bar at the top and click Connect. The token is stored in localStorage under the key _dlr_pat and will not be asked for again on the same device.
  3. The identity overlay appears. Select your name (Kevin Brittain, Mica Albovias, or Ericamae Atenta). Your choice is saved to localStorage under _task_user. The system defaults to showing your tasks in the team filter.
  4. Data loads automatically. The top bar shows the sync timestamp once loading is complete.
ℹ If the app is loaded inside the main platform iframe, it automatically inherits the parent window's PAT via window.parent.PAT and skips the auth bar entirely.
2

Returning visits

Daily use
  1. The page loads with your saved identity and PAT. No login is needed.
  2. Data is fetched from Airtable in parallel with calendar events on every load.
  3. Kevin's overdue tasks are automatically rescheduled to today in the background.
  4. To reload manually at any time, click Refresh in the top-right corner.
  5. To switch user, click Switch next to your name badge in the top bar. This clears the saved identity and shows the selector again.
📊 3. Task Views

The six views are accessible via the tab bar below the KPI cards. Each view serves a distinct purpose and may show a different subset of tasks.

☀ My Day

The default view. Shows today's tasks and overdue tasks for the active team member. Builds a visual day timeline from 08:00 to 18:00 (configurable) by slotting tasks into gaps between calendar events and routine blocks. Includes KPI row, capacity bar, deferred-task warnings, and inline status dropdowns.

✔ Tasks with no time estimate are still shown in the "Also Today" section below the timeline.
📋 Task List

A paginated table of every task that is not a Some Day task, whatever its priority. Each row shows task name, due date, status badge, assignee avatar, priority, time estimate, business, and recurring flag. Clicking any row expands it in-place to show description, metadata, attachments, a status dropdown, and an "Open in Airtable" link. Supports bulk selection.

ℹ Project-priority tasks show here as well. Kanban is a second way to see them laid out week by week, not the only place they appear. Completed tasks are hidden until you pick Completed (history) in the status filter, which fetches them separately.
📌 Kanban

A four-column week-by-week board showing only Project-priority tasks for the selected month. Columns are Week 1 (days 1–7), Week 2 (8–14), Week 3 (15–21), Week 4 (22–end). Each column header shows the date range and total hours allocated. Cards are draggable — dropping a card onto a different column updates the task's due date to the first day of that week in Airtable. Month navigation uses the Previous / Next buttons.

📁 Projects

A card grid of all projects from the Projects Airtable table. Each card shows project name, status badge, progress bar (completed tasks / total tasks), overdue count, and date range. Clicking a card expands it to show the Deliverable, Definition of Done, and up to 20 linked tasks. Filter by Active, Completed, or All. Projects sorted: active first, then by completion percentage descending.

📈 Capacity

Per-person utilisation cards showing total hours allocated vs. the 40 hr/week capacity constant. Colour coding: green below 70%, amber 70–90%, red above 90%. Each card breaks down hours by status and by priority. When "All" is selected in the team switcher, a Team Overview card appears across the top spanning the full grid width.

🔄 Recurring

All tasks where the Recurring field or Recurring? flag is set. Groups tasks by frequency: Daily, Weekly, Fortnightly, Monthly, Quarterly, Bi-Annually, Annually, Flagged. Shows summary KPIs (total recurring, hours per cycle, completed, overdue). Intended to identify candidates for AI agent automation.

ℹ All views respect the Team Switcher at the top. Selecting a person's name filters every view to only their tasks. Selecting All shows the whole team.

✏ 5. Creating & Editing Tasks
Creating tasks

You can create tasks on the page. There are four ways in, and every one writes straight to the Tasks table (tblqB8b22hKBL4PF1), so nothing needs re-typing in Airtable afterwards.

RouteWhere the button isWhat it does
+ Add Task Top bar of the page, the My Day action row, and the right-hand end of the Task List filter bar Creates the task immediately, then opens the Task Drawer with the title selected so you type straight over it. Fill in the rest inside the drawer.
+ Task (floating button) Bottom-right corner of every page in the platform Jumps to the Tasks page and opens the same Task Drawer. Use it when a task occurs to you while you are somewhere else.
+ Add Maintenance Task Contractor Tasks tab, above the job list Opens a short form: task name, contractor, description, property and priority (Low or High). Creates a contractor job with the Maintenance Ticket box ticked.
+ Create Project Projects tab, right-hand end of the Active / Completed / All row Opens the Add Project form. Creates a project, not a task, so you have something to link tasks to.

A task made with + Add Task starts with sensible defaults you can change in the drawer: due today, a 15-minute time estimate, priority Not Urgent, and the assignee set to whoever the team switcher is on, or to you. Status is worked out from the due date, so a due date in the future makes it Upcoming and today's date makes it Today. If you back out with Cancel, the placeholder task is deleted for you.

✔ Go to Airtable only for fields the drawer does not cover, such as attachments and less-used linked records. If you do create or edit a task there, click Refresh in the top bar to pull it into the page.
Editing task status (in-page)

Status can be changed without leaving the page in three ways:

  1. In My Day / timeline: click the Status button on any task card to open a dropdown with the five statuses (Today, Upcoming, Approval, Completed, Overdue). Or click Complete to jump straight to Completed.
  2. In Task List: expand a task row, then use the Change Status dropdown in the detail panel. The page re-renders immediately after the Airtable PATCH request succeeds.
  3. In My Day / card list: click the Status button on a card card, or click Done to mark Completed directly.

All status changes call patchTask(taskId, { [F.status]: { name: newStatus } }) which sends a PATCH request to https://api.airtable.com/v0/{BASE_ID}/{TASKS_TABLE}/{taskId} with typecast: true.

Editing due dates (in-page)

Due dates can be updated in these ways:

  • Drag a Kanban card to a different week column. The due date is set to the first day of the target week.
  • Click Defer to tomorrow in the Plan My Day overlay. This sets the due date to tomorrow's date.
  • The bulk Reschedule Selected button sets the due date to tomorrow for all ticked tasks.

All due-date changes call updateTaskDueDate(taskId, newDate) which sends a PATCH to the same endpoint with field fld7XP8w8kbxfETV4.

Opening in Airtable

In the Task List expanded row, an Open in Airtable button opens the record directly at https://airtable.com/{BASE_ID}/{TASKS_TABLE}/{recordId} in a new tab. Use this for full editing (all fields, attachments, linked records).

🗓 6. Smart Daily Planner
How the planner works

The Smart Daily Planner is triggered when the My Day view loads and also when Plan My Day is clicked. It calls buildDayTimeline(todayTasks, overdueTasks, calEvents, routineBlocks) to construct a minute-by-minute schedule for the working day.

Algorithm (in order)

  1. Place calendar events as fixed blocks. All-day events are shown separately and do not block slots. Timed events are placed by parsing their start/end times to minutes since midnight.
  2. Place routine blocks using placeRoutineBlocks(). The "Run" block is placed first (preferred afternoon = 14:00). Lunch is placed next with the rule "must finish 2 hrs before Run". "Get Ready" is placed at the start of the working day. Any custom blocks are placed in order.
  3. Find free slots using findFreeSlots(). A slot must be at least 15 minutes long to be used.
  4. Schedule tasks into free slots in priority order (Urgent first, then High, then Not Urgent). Overdue tasks are included before today's tasks. Each task uses its timeDur field (seconds, converted to minutes) if set; otherwise it falls back to timeEst name (e.g. "1 hr" = 60 min); otherwise defaults to 30 minutes.
  5. Deferred tasks are those that could not fit in any remaining slot. They appear in the "Won't Fit Today" warning section.
Routine configuration

Click Configure Routine in the My Day view to open the routine editor panel. Settings are saved to localStorage and persist between sessions.

SettinglocalStorage keyDefault value
Routine blocks (name, duration, preferred time, rule) _task_routine Get Ready (30 min, morning), Lunch (30 min, midday, before-run-2h), Run (60 min, afternoon)
Working hours config (start, end, max task hours) _task_workconfig Start: 8:00, End: 18:00, Max task hours: 6
ℹ The available rule options for a routine block are None and 2h before Run. Click Reset to Defaults to remove saved settings from localStorage and restore the three default blocks.
Plan My Day overlay

Clicking Plan My Day opens a modal overlay showing:

  • Two KPI tiles: total task time vs. total free time
  • If overcommitted: a warning with the excess amount, and a Defer to tomorrow button for each suggested deferral (lowest-priority tasks first)
  • If capacity is OK: a confirmation that all tasks fit
  • A list of scheduled tasks with their proposed time slots (start time — end time, duration)

Clicking outside the modal or pressing Close dismisses it.

Auto-reschedule (Kevin only)

Every time data loads, autoRescheduleOverdue() runs automatically for Kevin's account. It finds all tasks where:

  • Assignee email = kevin@runpreneur.org.uk
  • Due date is before today
  • Status is not "Completed"
  • someDay field is not set
  • Hard Deadline is not ticked

A hard deadline is a fact about the outside world — a court date, a filing window, a contractor's booked slot. Moving it would hide a missed commitment rather than manage it, so the task stays where it is and shows as overdue until you deal with it.

For each matching task it sets the due date to today. If the task has no origDueDate yet, it also saves the original due date to the fldS2OR7oQKC7T1to field. Patches are sent in batches of 10 with a 250 ms delay between batches to avoid rate limits, and each one is checked: only the tasks Airtable actually accepted are counted or moved on screen.

⚠ This runs silently on load. The My Day view shows a notice confirming how many tasks were rescheduled. It does not run for Mica or Ericamae.
📅 7. Calendar Integration
How Google Calendar data is fetched

The page calls fetchCalendarEvents() on every data load. This makes a GET request to the Google Apps Script proxy URL configured in the constant GCAL_SCRIPT_URL at the top of the script, passing today's date as a query parameter (?date=YYYY-MM-DD).

The proxy (deployed as a Google Apps Script web app) returns a JSON object with an events array. Each event must have: summary, start, end, optionally location, and allDay. Start and end can be either HH:MM or an ISO datetime string.

⚠ If GCAL_SCRIPT_URL is empty, calendar fetching is skipped silently and a "Calendar: not connected" note appears in the My Day action bar. The rest of the page still works normally.
Calendar events in My Day

Once fetched, calendar events appear in the My Day timeline as blue "CALENDAR" blocks. All-day events appear in a separate "All-Day Events" section above the timeline, not as time-slot blocks. The count of calendar events for today is shown in the My Day KPI row and in the page subtitle.

✔ Calendar events are treated as immovable fixed blocks. The planner will not place tasks or routine blocks during calendar event time slots.

Purpose and access

Open os/tasks/index.html and click the Contractor Tasks tab in the view bar. It shows every open maintenance job across the portfolio, grouped by the property the job belongs to.

Contractors: Gary Marsh, Rob Jackson, Roy Lavin. Same Airtable base and tasks table as the rest of the page (appnqjDpqDniH3IRl, tblqB8b22hKBL4PF1) — the tab is a filter over the tasks already loaded, so it needs no extra fetch and no separate login.

Rows are grouped by property (the linked Rental Unit) and carry: Task · Description · Property · Created · Age · Priority · Status · Attachments. Priority and Status are editable in place from the row itself.

Where a job has no property linked, the page tries to match one from the task text against the known property names and offers it. Nothing is written until you accept it.

Sort order

Tasks are sorted by sortTasks(): overdue first (regardless of stated status), then by status order (Overdue 0, Today 1, Approval 2, To do 3, Upcoming 4), then by priority order (Urgent 0, High 1, Project 2, Not Urgent 3), then by due date ascending.

ℹ Filters stack. Each one you set narrows what the one before it left, so "AI agents only" plus "Overdue" gives you overdue agent work. Clear Filters at the end of the bar resets all eight, the search box and the completed date range in one click.

ℹ Sorting is automatic, there is no sort dropdown. The list runs by due date, soonest first, with undated tasks at the bottom, and tasks sharing a due date are ordered Project, Urgent, then Not Urgent. In "Completed (history)" the order flips to most recently completed first.
Kanban project filter

A dropdown in the Kanban controls bar lists all unique project names found across tasks with priority "Project". Selecting a name sets kanbanProjectFilter and re-renders the board. Tasks with no matching project ID or name are excluded.

Recurring view groups

The Recurring view groups tasks by their recurring frequency field value. The display order is hard-coded as: Daily, Weekly, Fortnightly, Monthly, Quarterly, Bi-Annually, Annually, Flagged. "Flagged" captures tasks where the Recurring? checkbox is true but the recurring text field is empty.

🤖 12. AI Agents & the Approval Gate

The short version. AI agents do the work and then stop. They send nothing, file nothing and change nothing until you say yes. You say yes either in the task drawer or with an emoji in the #agent-approvals Slack channel. Saying yes hands the task back to the agent, and the agent then does the thing and marks it done. Approving is not the same as the work being finished.

What you see, and what to click

  • Approve — the work is right as it stands. It goes back to the agent to carry out.
  • Approve with minor edits — you tidied it, but it was basically right. Still counts as accurate for that agent.
  • Request changes — back to the agent to redo. You have to say what needs changing; the button will not submit without it. Nothing has gone out, so nothing needs undoing.
  • Reject — closed with a reason. Counts against that agent.

Approving from Slack while you are away

Every task entering Approval is posted to #agent-approvals within a minute. The post carries what the agent actually produced, so you can judge it from your phone without opening Airtable.

  • ✅ approve — the agent goes and does it, then closes the task.
  • ❌ reject — kill this piece of work entirely. Use it when the task should not happen at all, not when it needs redoing. The task is closed as Completed with the outcome recorded as Rejected, so it leaves your board and nothing is carried out. It counts against that agent's accuracy. Note that a rejected task still counts as a completed task in the Team Member rollups; the accuracy score is the number that reflects the rejection.
  • changes: just reply in the thread. No emoji. Type what you want different and that goes straight back to the agent as the instruction. Replying is the amendment.

Only your reactions and your replies count. If you tap the pencil out of habit, the bot asks you what to change rather than guessing.

If the task changed after the message was posted, an approve or a reject is refused. The bot says so in the thread and posts the task again as it then stood, so an emoji can never release something you did not actually read. A reply asking for changes is never refused, because sending feedback back to an agent puts nothing out into the world.

Where the agent's work lives

Two different things, kept in two different fields. Description is the brief the agent was given. Agent Output is what it produced and is proposing — the drafted email, the findings, the change it intends to make. Agent Output is what you see in Slack and at the top of the approval block. An agent that leaves it empty gets a warning on the post rather than a quiet approval, because there would be nothing to judge.

When you ask for changes, your words are saved to Approval Feedback on the task. That is what the agent reads before its next attempt.

Adding a new AI agent

Three ticks, no developer. In the Team Members table: add a row, give it a name, tick Is AI Agent, tick Active. It then appears in the AI Agents filter and in every assignee picker, and you can hand work to it straight away.

Agents need no Airtable login and no paid seat — logins are managed separately. The name does not matter; the tick box is what makes it an agent.

Seeing what the agents are doing

An AI agent cannot be an Airtable Assignee — that field only holds real logins. Agent work sits on the Team Member link instead. The team bar has an AI Agents button showing everything the workforce holds, with a dropdown to narrow to one agent, and agent tasks show an AI badge in the Assignee column. You can hand a task to an agent from the same dropdown you use for people.

Unassigned now means nobody at all, human or agent. Before this, agent work counted as unassigned and looked like a backlog nobody owned.

The AI Agents tab

Shows what is waiting on you, and how accurate each agent has been at each kind of work — scored separately, because an agent can be excellent at drafting and poor at analysis.

An agent that reaches 20 decisions of one kind of work at 90% or better, with no rejections in its last 10, appears as a recommendation, and the same line comes up in the 09:00 huddle. It is only ever a recommendation. Nothing is promoted automatically, and no agent ever escapes the gate unless you decide it should.

What agents are never allowed to touch

The restraint order, Operation Lily, the criminal investigation, the liquidations, and money owed to you personally by parties in that matter. Creditor and debt correspondence is Mica's, including high value. If one of these reaches the approval queue anyway, the Slack post carries a red warning — treat that as a fault to investigate, not a task to approve.

🔧 13. Troubleshooting
Page shows "Failed to load data" or "Invalid token. Please re-enter your PAT"
Your Airtable PAT has expired or is incorrect. The auth bar reappears automatically when the API returns a 401 or 403. Enter a valid PAT and click Connect. This clears the stored token and retries.
Page asks for a PAT on every load even though I already entered it
The page is running in a context where localStorage is blocked (private/incognito mode, or an iframe with restricted storage). Use a regular browser tab, or ensure the platform shell is loaded first so the child iframe inherits the parent's PAT via window.parent.PAT.
Tasks I just created in Airtable are not showing
Click Refresh in the top bar. The page only fetches data on load and on explicit refresh — it does not poll Airtable in the background.
The Kanban board is empty
The Kanban view shows only tasks with priority "Project". Check that your tasks are assigned the "Project" priority in Airtable. Also check the month navigation — tasks are placed by their due date, so a different month may be selected.
My Day timeline shows no calendar events
Check that GCAL_SCRIPT_URL is set in the script constants and that the Google Apps Script proxy is deployed and accessible. If the constant is empty, a "Calendar: not connected" note appears in the My Day action bar. Calendar fetch errors are logged to the browser console.
Auto-reschedule ran but some overdue tasks were not rescheduled
Auto-reschedule only runs for Kevin (key "kevin"). It skips two kinds of task: someDay tasks, and anything with Hard Deadline ticked — a hard deadline is a real-world commitment, so moving it would hide a miss rather than manage it. Check the signed-in user is Kevin, and check both of those fields on the task in Airtable. If a task meets every condition and still did not move, Airtable refused the write: the browser console logs which task and which status code, and the count on screen only ever includes the ones that landed.
Status change button does not update; page re-renders but old status shows
The PATCH request may have failed silently. Open the browser console and check for errors. Common cause: the PAT lacks write permission on the tasks table. Ensure the PAT has "create records, update records" scope on the base.
A contractor's jobs are missing from the Contractor Tasks tab
First: if you or the contractor are on a jobs.html link, that page was deleted on 24 Apr 2026 — use the Contractor Tasks tab in os/tasks/index.html instead. If the tab is open and a person's count reads zero, the job is matched on the Assignee email, not on the old Contractor field: check the task's Assignee is the contractor's real address (Gary gkm.property.maintenance@outlook.com, Rob rjm320@hotmail.com, Roy roy.lavin1978@gmail.com). A job with no contractor on it appears under Unassigned if it is a maintenance ticket.
Capacity view shows 0 hrs for a team member who has tasks
Capacity calculates hours using timeDur (seconds field) first, then timeEst (select field). If neither is set, the task contributes 0 minutes. Ensure tasks have a Time Estimate or Time Duration set in Airtable.
Drag-and-drop on the Kanban board does not update the due date
The drop handler calls updateTaskDueDate(draggedTaskId, weekStartDate) which requires a successful PATCH. If the API call fails, the card visually moves but reverts on the next render. Check the browser console for errors and verify PAT write permissions.
